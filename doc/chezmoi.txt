1. INTRODUCTION                                                *chezmoi-intro*

chezmoi.nvim makes the chezmoi source the only place a managed dotfile is
edited:

- Opening a managed target (for example `~/.bashrc`) opens its source
  (`dot_bashrc`) instead, with the filetype of the target.
- Writing a source applies exactly its target and reports the result.
- `:Chezmoi` adds, forgets, applies, previews templates and refreshes.

Every chezmoi invocation runs asynchronously. Scripts (`run_*`) are never
executed by the plugin. Encrypted files, symlinks and externals are ignored.

Requirements: Neovim >= 0.12, chezmoi >= 2.70 on `PATH`.

==============================================================================
2. SETUP                                                       *chezmoi-setup*

                                                             *chezmoi.setup()*
require('chezmoi').setup({opts})
    Activates redirect and apply-on-save and builds the index of managed
    files in the background. Returns without waiting for chezmoi. Calling it
    again replaces the options and rebuilds the index.

    Without `setup()`, the first `:Chezmoi` command calls it with defaults.
    Load the plugin at startup (not only on the command) so that redirect and
    apply-on-save are active from the start.

==============================================================================
3. OPTIONS                                                   *chezmoi-options*

Defaults: >lua
    require('chezmoi').setup({
      cmd = 'chezmoi',      -- chezmoi executable
      redirect = true,      -- open the source when a managed target is opened
      apply_on_save = true, -- apply the target when its source is written
    })
<

==============================================================================
4. COMMANDS                                                 *chezmoi-commands*

                                                                    *:Chezmoi*
:Chezmoi {subcommand} [args]
    Subcommands and aliases complete with <Tab>.

:Chezmoi add [args]                                             *:Chezmoi-add*
:Chezmoi manage [args]
    Add the file of the current buffer to chezmoi and show its new source in
    the window. Extra arguments are passed to `chezmoi add`, for example
    `--template`. Refuses a buffer with unsaved changes, without a file, or
    already managed.

:Chezmoi forget                                              *:Chezmoi-forget*
:Chezmoi unmanage
    After confirmation, stop managing the file of the current buffer (target
    or source), delete its source and keep the target, which is then shown
    in the window. Refuses an unmanaged buffer or one with unsaved changes.

:Chezmoi apply                                                *:Chezmoi-apply*
    Apply the target of the current buffer (target or source), whatever the
    value of `apply_on_save`.

:Chezmoi preview                                            *:Chezmoi-preview*
    Render the current template source (a source ending in `.tmpl`),
    including unsaved changes, and show the result in a read-only vertical
    split next to it, with the filetype of the target. The cursor stays in
    the source. Running the command again re-renders into the same window.
    For any other buffer it explains why there is nothing to preview; a
    template that fails to render reports chezmoi's error.

    The preview is not live. It is re-rendered when its source is written,
    whatever the value of `apply_on_save`, and when the command is run
    again. In between, the winbar shows `[stale]` as soon as the source
    changes, highlighted with |hl-ChezmoiPreviewStale|. A failed render keeps
    the previous content and marks it stale. Closing the preview window
    stops all refreshing.

    The template is rendered from the buffer text, not the file, so
    `.chezmoi.sourceFile` is `"stdin"` in the preview.

                                                      *hl-ChezmoiPreviewStale*
ChezmoiPreviewStale
    Stale mark in the preview winbar. Linked to |hl-WarningMsg| by default.

:Chezmoi refresh                                            *:Chezmoi-refresh*
    Rediscover the source directory and rebuild the index, for example after
    `chezmoi add` in a shell.

Targets changed outside chezmoi are never overwritten: the apply fails with an
error naming the target. Resolve it with `chezmoi diff` or `chezmoi merge` in
a shell.

==============================================================================
5. LUA API                                                       *chezmoi-api*

All functions answer from the in-memory index and run no process. Before the
index is ready, every buffer is reported as not managed.

                                                        *chezmoi.is_managed()*
require('chezmoi').is_managed({buf})
    True when the file of {buf} (0 or nil: current buffer) is a managed
    target or the source of one. Suitable for statuslines: >lua
        function() return require('chezmoi').is_managed(0) and 'chezmoi' or '' end
<
                                                         *chezmoi.source_of()*
require('chezmoi').source_of({path})
    Absolute source path of the managed target {path}, or nil.

                                                         *chezmoi.target_of()*
require('chezmoi').target_of({path})
    Absolute target path of the source {path}, or nil.

==============================================================================
6. HEALTH                                                     *chezmoi-health*

`:checkhealth chezmoi` reports the Neovim and chezmoi versions, the source
directory (or chezmoi's error for it) and the number of indexed files.
